# HDLC engine

Covers `HdlcStateMachine`, `HdlcFrame`, `HdlcFrameKind`, `HdlcConnectionState`, `HdlcReceiveResult`, and `HdlcFrameException` (all internal, namespace `BlueHeighliner.MicroGate.Hdlc`), which read their poll/final and window settings from `MicroGatePeerOptions`. Together they turn raw frame bytes into frames and back and track the asynchronous balanced mode (ABM) connection. The engine has no I/O of its own: transports move raw bytes, and this engine decides what those bytes mean and what to send back. Background: https://en.wikipedia.org/wiki/High-Level_Data_Link_Control.

## ADCCP conformance

ADCCP (ANSI X3.66, Advanced Data Communication Control Procedures) is the ANSI counterpart of HDLC, and the two share their frame formats and, for ABM, their procedures. The engine implements the ABM subset of both: the basic (8-bit address, 8-bit control) frame format, modulo-8 sequence numbers, and the I, RR, RNR, REJ, SABM, DISC, UA, DM, and FRMR frames, with the standard control field encodings. Beyond the frame kinds, it follows these procedures: command and response addressing (see Addressing); DM in answer to a DISC, or to an I or supervisory frame, received while disconnected, and to the mode-setting commands it does not support (SNRM, SNRME, SARME, and SABME, since it never leaves ABM or modulo-8 numbering); FRMR, with the rejected control field and the W flag, in answer to a command with an undefined control field (including SREJ, which it does not use); an echoed TEST response; UI and XID ignored rather than rejected; the final bit answering a poll (see Disabling the poll/final bit); and a peer's RNR pausing sends until it sends anything else.

What it does not do: extended (multi-byte) addresses, modulo-128 numbering (SABME), selective reject, NRM and ARM, and the XID and UI procedures. Recovery from a lost acknowledgement resends every outstanding frame when the timer expires, rather than first polling the remote station with an RR that has the poll bit set and resending from the N(R) in its final response; a compliant remote station discards the duplicates, and the result is only different in how much is sent. A received FRMR ends the link instead of resetting it with a new SABM, and an N(R) outside the outstanding frames is ignored instead of raising a frame reject, so neither can leave a link half-reset. Setting `DisablePollFinalBit` (its default) keeps the poll/final bit at zero, which ADCCP allows for the mode-setting frames but which a remote station that polls and waits for a final response cannot work with.

## Base API versus link layer

The platform SDKs' base API only does bit-level framing: 0x7E flag detection, zero-bit insertion for transparency, and CRC generation and checking. The driver returns and accepts exactly the bytes between the flags; one read or write is exactly one frame, and no address or control structure is enforced. Each frame written is built as address byte, control byte, then payload, and each frame read is parsed back the same way.

## Control field encoding

The basic (modulo 8, non-extended) control field:

| Frame type | Bit 0 (LSB) | Bits 1 to 3 | Bit 4 | Bits 5 to 7 |
| --- | --- | --- | --- | --- |
| Information (I) | `0` | N(S) | P/F | N(R) |
| Supervisory (S) | `1` | `0` + SS (2 bits) | P/F | N(R) |
| Unnumbered (U) | `1` | `1` + 2 modifier bits | P/F | 3 modifier bits |

`HdlcFrame` encodes and decodes this with bitmasks, using the control byte values of the Linux kernel's LAPB implementation, which are standard across HDLC, SDLC, and LAPB:

| `HdlcFrameKind` | Control byte (P/F = 0) |
| --- | --- |
| `SetAsynchronousBalancedMode` (SABM) | `0x2F` |
| `Disconnect` (DISC) | `0x43` |
| `UnnumberedAcknowledge` (UA) | `0x63` |
| `DisconnectedMode` (DM) | `0x0F` |
| `FrameReject` (FRMR) | `0x87` |
| `ReceiveReady` (RR) | `0x01` |
| `ReceiveNotReady` (RNR) | `0x05` |
| `Reject` (REJ) | `0x09` |
| `Information` (I) | `0x00`, plus N(S) and N(R) |

The poll/final (P/F) bit is always bit 4 (`0x10`) regardless of frame type, so it is applied uniformly by OR-ing it into whichever base value applies. `HdlcFrame.Parse` throws `HdlcFrameException` for frames shorter than an address and control field or with a control byte matching no known kind; transports drop such frames and keep reading.

## Addressing

ADCCP and HDLC address a command with the address of the station it is sent to, and a response with the address of the station sending it. The state machine is constructed with this station's `address` and the `remoteAddress`, which must differ (`MicroGatePeer.Connect` requires two different addresses, so a station can always tell a command from a response by its address). Commands (SABM, DISC, and I-frames) go out addressed to the remote address, and responses (UA, DM, FRMR, and the RR, REJ, and DM answering received frames) go out with this station's address. On receipt, commands must carry this station's address and responses the remote address; anything else is ignored with no state change and no response. A received supervisory command with the poll bit set is answered with an RR that has it set as final, and an unrecognized command addressed to this station is answered as described above. `0xFF` is the all-stations (global) address of ANSI X3.66 4.4: a command addressed to it is accepted exactly like one addressed to this station and answered with a response carrying the station's own address, as the standard asks of a station that accepts it, while a response addressed to it is ignored. SABM requests are always sent to `0xFF`, as the stations this was checked against do, so a request needs no knowledge of the remote address; every other command goes to the remote address.

## Disabling the poll/final bit

The bit is used only where the procedures need it. SABM, DISC, and information frames are sent with it clear; UA, RR, REJ, and DM responses mirror the poll bit of the frame they answer back as final, so a polling station gets its final response; and when sent data goes unacknowledged the timeout procedure polls with an RR command that has it set (see Acknowledgement and retransmission). `MicroGatePeerOptions.DisablePollFinalBit` forces it to 0 on every frame in both directions, including responses to a peer frame that had it set; without the bit the timeout procedure cannot poll and falls back to sending the outstanding frames again.

## Connection state machine

`HdlcConnectionState` moves `Disconnected`, `Connecting`, `Connected`, `Disconnecting`, `Disconnected`.

- **Connect**: `CreateConnect` sends SABM (poll clear, to the all-stations address) and moves to `Connecting`. UA while `Connecting` moves to `Connected` and resets both sequence numbers to 0. A SABM from the peer at any time also moves straight to `Connected` and is answered with UA, so both ends may call connect at the same time with no fixed initiator, matching two combined stations under ABM.
- **Disconnect**: `CreateDisconnect` sends DISC and moves to `Disconnecting`. UA while `Disconnecting` moves to `Disconnected`. A DISC from the peer at any time moves to `Disconnected` and is answered with UA, or with DM if this side was already disconnected. DM or FRMR at any time moves to `Disconnected` with no reply. While `Disconnected`, an I-frame or supervisory frame is answered with DM (final set if it was polled) rather than ignored, so a remote station that still thinks the link is up finds out.
- **Peer busy**: an RNR sets `PeerBusy` and any later I-frame or supervisory frame other than RNR clears it. `MicroGatePeer` waits on it before taking a send window slot, so nothing new is sent to a station that said it cannot accept it. Frames already outstanding are unaffected and still resent by the timer.
- **Data transfer**: `CreateInformation` (only while `Connected`, otherwise `InvalidOperationException`) builds an I-frame carrying the current N(S) and expected N(R), advances N(S) modulo 8, and keeps the payload until the frame is acknowledged: the `ReadOnlyMemory<byte>` overload copies it into memory rented from `MemoryPool<byte>`, and the `IMemoryOwner<byte>` overload takes the caller's owner and keeps it without copying (ownership passes only if the call succeeds). Every retained owner is disposed when its frame is acknowledged, taken back by `DiscardLastInformation`, dropped by a link restart, or still outstanding when the state machine is disposed; a link reset that keeps the frames and renumbers them does not dispose them. At most 7 frames may be outstanding, the largest window that stays unambiguous with modulo 8 numbering; an eighth throws. On receipt, an I-frame whose N(S) matches the expected receive sequence is accepted: the payload is delivered, the expected sequence advances, and the acknowledgement is deferred: the state machine only notes that one is pending, so the N(R) can ride on the next information frame this station sends (any frame it builds carrying the current N(R), including resends and polls, clears the note), saving a frame when data flows both ways. If nothing carried it, `CreateAcknowledgement` produces an RR when the caller's timer (`AcknowledgeDelay`) expires. Acknowledgement is not deferred for a frame with the poll bit set, which must be answered with a final response at once, for a gap (REJ or RR at once), when four frames are already waiting, or when `AcknowledgeDelay` is zero. An out-of-order N(S) delivers nothing and returns REJ, but only for the first one of a gap: later out-of-order frames are answered with RR until the missing frame arrives, so a burst of frames after a loss produces one REJ and one resend, not many. Answering with RR rather than nothing matters when the REJ itself is lost and the sender's timer resends frames the receiver already has: the RR still acknowledges them, where silence would look like a dead link and eventually exhaust the sender's retransmission limit.
- **Acknowledgement and retransmission**: every RR, RNR, REJ, and I-frame carries the peer's N(R), the number of the next frame it expects, which acknowledges every outstanding frame before it. An N(R) that does not fall within the outstanding frames is ignored. REJ additionally flags that the frames still outstanding must be sent again; the caller then obtains them, oldest first, from `CreateRetransmission` at the moment it writes them, which is also what the resends that follow a poll answer use. The timeout procedure, `CreateTimeoutRecovery`, does not blindly resend: it creates one RR command with the poll bit set, as ADCCP and HDLC prescribe, and remembers that a poll is outstanding. The remote station must answer with a final response carrying its N(R); that acknowledges what it received, and if frames remain outstanding they were lost, so they are flagged for resend, unless the answer was RNR. This matters for stations that acknowledge lazily, only by piggybacking on their own data or when polled: resending a frame such a station already has would get no answer at all. Resent frames are rebuilt with the current N(R). A link reset restarts both sequence numbers at zero but does not lose data: a SABM received while connected keeps the outstanding frames, renumbers them from zero, and flags a resend. The state machine counts the requests it has sent that are still unanswered, so a UA answering a request sent while already connected (the answer to a retry that crossed the first answer) resets this side too, matching the remote side, which resets on every SABM; a UA with no request outstanding is ignored. A SABM received while not connected discards stale outstanding frames and reports them as acknowledged so the caller can release its window. `DiscardLastInformation` takes back the newest frame and its sequence number, for a frame that could not be written.

`HdlcReceiveResult` reports the resulting state, an optional delivered payload (referencing the memory the frame was received into, so it is valid only until that memory is reused), an optional response frame the caller must transmit, the number of frames acknowledged, and whether the outstanding frames must be sent again. `HdlcFrame.Parse` likewise slices its input rather than copying it.
